# SnapBack

**Верните сеанс Windows к состоянию «сразу после запуска» — без перезагрузки.**

Сразу после входа в систему Windows находится в относительно чистом состоянии: системные процессы,
автозагрузка — и всё. Через несколько часов работы добавляются браузеры, Discord, Telegram, IDE,
процессы Python и Node.js, лаунчеры и фоновые помощники. SnapBack запоминает чистое состояние
(**baseline**), показывает, что появилось после него, и **вежливо** закрывает лишние приложения —
так же, как если бы вы нажали ✕: приложения успевают сохранить данные или спросить вас.

SnapBack — **не** «очиститель памяти» и не «ускоритель». Он не урезает working set, не очищает
standby list, не отключает службы, не правит реестр и не удаляет файлы. Он закрывает только те
приложения, которые вы запустили после baseline, и только с вашего согласия.

## Как это работает

1. **Baseline.** Нажмите «Make current state the baseline» (или включите автоматическое создание:
   через несколько минут после входа, когда программы автозагрузки закончат запуск). Baseline хранит
   **приложения**, а не просто PID.
2. **Сравнение.** SnapBack группирует процессы в приложения (30 процессов `chrome.exe` — одно
   приложение; VS Code со всеми помощниками — одно приложение) и сравнивает их с baseline.
3. **Просмотр.** Вы видите, что появилось после baseline: иконка, память, число процессов, оценка риска:

   | Приложение            | Память | Оценка                     |
   |-----------------------|-------:|----------------------------|
   | Discord               | 650 MB | Safe                       |
   | Visual Studio Code    | 1.4 GB | Possible unsaved data      |
   | python.exe — train.py | 740 MB | Manual review              |
   | Google Chrome         | 3.2 GB | Was present in baseline    |

   Заранее отмечены только приложения с оценкой **Safe**. Любое можно снять или добавить в список
   «Всегда оставлять».
4. **Предварительный просмотр.** До любого действия показывается каждый шаг («отправить запрос на
   закрытие 2 окнам Code.exe (PID 1234)», «не трогать conhost.exe — компонент Windows», …).
   **Dry run** проверяет все шаги на живой системе, ничего не меняя.
5. **Вежливое закрытие.** Выбранные приложения получают обычный запрос на закрытие и время на
   сохранение. Ничего не завершается принудительно.
6. **Ваше решение.** Приложения, которые не закрылись (например, спрашивают «Сохранить изменения?»),
   показываются отдельно. Можно переключиться на них и нажать «Check again» — или отдельно и явно
   выбрать принудительное завершение конкретных приложений.
7. **Результат.** Сколько приложений закрыто, сколько памяти они занимали и как изменилась доступная память.

## Безопасность прежде всего

SnapBack исходит из того, что **закрыть не тот процесс намного хуже, чем закрыть слишком мало**.
Подробно — в [docs/SAFETY.md](docs/SAFETY.md).

- **Только ваши приложения в вашем сеансе.** Процессы других пользователей и сеансов, службы,
  процессы с правами администратора, критические и защищённые (PPL) процессы, компоненты Windows
  (всё из `C:\Windows`, оболочка, антивирус и т.д.) **защищены**. Нет настройки, которая сняла бы защиту.
- **Fail closed.** Если какой-либо важный для безопасности факт о процессе проверить не удалось
  (владелец, путь, повышение прав, флаг критичности, уровень защиты), процесс считается защищённым.
- **PID никогда не используется в одиночку.** Процесс идентифицируется парой *PID + время создания*.
  Перед каждым действием идентичность, путь к исполняемому файлу, сеанс, владелец и защита
  перепроверяются **на том самом дескрипторе, через который выполняется действие**, поэтому
  переиспользованный PID не может быть задет.
- **Три независимых уровня защиты:** классификатор, safety guard (повторная проверка живого процесса
  прямо перед действием) и уровень Windows (проверка дескриптора). Ошибка в интерфейсе не может
  привести к закрытию защищённого процесса.
- **Вежливо по умолчанию, принудительно — только по запросу.** Оконные приложения получают
  `WM_CLOSE`. Приложения в трее — запрос через Windows Restart Manager (механизм установщиков)
  **без** флага принудительного завершения. Консольные программы — Ctrl+C, и только если их консоль
  не разделена с посторонними программами. Принудительное завершение требует отдельного подтверждения,
  которое действует только для конкретных экземпляров процессов и истекает через 5 минут.
- **Без прав администратора, без драйвера, без служб.** SnapBack работает как обычный пользователь
  (`asInvoker`) и вообще не работает со службами Windows.

## Требования

- Windows 10 (1809+) или Windows 11, x64 или ARM64.
- Релизные сборки самодостаточны — отдельная установка .NET не нужна.

## Установка

Скачайте `SnapBack-<версия>-win-x64.zip` (или `win-arm64`) со страницы [Releases](../../releases),
распакуйте в любую папку (например, `%LOCALAPPDATA%\Programs\SnapBack`) и запустите `SnapBack.exe`.

Установщика нет, ничего не регистрируется в системе. Для удаления отключите автоматический baseline
в настройках (если включали), удалите папку и `%LOCALAPPDATA%\SnapBack`.

## Использование

### Окно программы

- **Make current state the baseline** — текущее состояние становится чистым.
- **New since baseline** — кандидаты на закрытие, с флажками.
- **Kept** — приложения из baseline и списка «Всегда оставлять». Новые окна и дочерние процессы этих
  приложений не являются причиной их закрывать.
- **Protected** — всё, что SnapBack никогда не тронет, с причиной.
- **Return to baseline…** — открывает предварительный просмотр; без подтверждения ничего не происходит.
- **Always keep selected** — добавить приложения в список «Всегда оставлять» (whitelist).
- **History** — последние операции. **Settings** — таймаут, автоматический baseline, whitelist.

### Автоматический baseline (необязательно)

Включите *Create a baseline automatically after I sign in* в настройках. SnapBack добавит себя в
автозагрузку текущего пользователя (ключ `Run` — единственная запись в реестр), при входе дождётся,
пока пройдёт минимум 2 минуты **и** 45 секунд не будут запускаться новые приложения (оба значения
настраиваются, максимум — 10 минут), создаст baseline и завершится. В этом режиме он ничего не закрывает
и сохраняет существующий baseline текущей загрузки.

### Командная строка

```text
snapback status                       baseline, приложения, память, что нового
snapback baseline create [--force]    сделать текущее состояние базовым
snapback baseline show [--all] [--json]
snapback list [--all] [--json]        приложения, запущенные после baseline
snapback preview [выбор] [--json]     dry run: все шаги и вердикт проверок
snapback restore [выбор] [--yes]      попросить выбранные приложения закрыться (без принуждения)
snapback history [--json]

выбор: --app <имя> (можно несколько) | --include-caution | --include-review
```

CLI намеренно **не умеет** завершать что-либо принудительно.

## Сборка из исходников

Нужен [.NET SDK 10](https://dotnet.microsoft.com/download) (см. `global.json`).

```powershell
git clone https://github.com/IT-Shelter-Labs/SnapBack-Rebootless.git
cd SnapBack-Rebootless
dotnet build SnapBack.sln -c Release
dotnet test SnapBack.sln -c Release
dotnet run --project src/SnapBack.App

# Самодостаточная сборка в один файл
dotnet publish src/SnapBack.App -c Release -r win-x64 --self-contained -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -o publish
dotnet publish src/SnapBack.Cli -c Release -r win-x64 --self-contained -p:PublishSingleFile=true -o publish
```

Платформонезависимое ядро и его тесты (140+) собираются и запускаются также на Linux и macOS.

## Данные и приватность

Всё хранится в `%LOCALAPPDATA%\SnapBack` (можно переопределить переменной `SNAPBACK_DATA_DIR`):
`settings.json`, `baseline.json`, `history.json` и логи в `logs\` (хранятся 14 дней). Заголовки
окон и командные строки показываются только в интерфейсе и никогда не записываются на диск или в лог.
SnapBack не обращается к сети.

## Архитектура

См. [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md): ядро (`SnapBack.Core`) принимает все решения и
полностью покрыто тестами; слой `SnapBack.Windows` только выполняет системные вызовы с проверкой
дескрипторов; `SnapBack.App` (WPF) и `SnapBack.Cli` — интерфейсы.
